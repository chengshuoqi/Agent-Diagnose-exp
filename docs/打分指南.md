# 人工打分指南

目标：对每条 agent 轨迹的**四个能力维度**打 1–4 分，再单独对**任务目标本身**打 1 分。全程不需要判断"任务最后成没成功"。

---

## 0. 先记住三件事

1. **你评的是过程，不是结果。** 答对了但过程一塌糊涂，分数应该低；答错了但过程严谨，分数可以高。
2. **五列里只有最后一列不看轨迹。** `objective_quality` 只读任务目标那句话；前四列才看 agent 做了什么。
3. **不要打开 `scores.json`。** 那是机器打分，先看会锚定你的判断。标注完成后再对比。

---

## 1. 你手上会有什么

`annotations.csv`（或 `annotations.md`）里每条轨迹包含：

| 字段 | 内容 |
|---|---|
| `task_id` | 任务编号（t01…t10） |
| `objective` | 任务目标原文 |
| `success` | 程序判定的成败，**仅供参考，不要拿它推分数** |
| `n_steps` | 步数 |
| `trace` | 每一步的 `Action` + `Reasoning` + 一小段页面观测 |
| 五列分数 | 待你填 |

一条 trace 长这样（t01 的真实样子）：

```
1. submit(8, "backpack")
   理由：我需要把 backpack 输入搜索框并提交。
   页面：... [8] combobox 'Search' ... [10] button 'Search' ...

2. send_msg_to_user("The first product is the Endurax ... priced at $119.99.")
   理由：搜索结果已显示，第一条是 Endurax，价格 $119.99。
   页面：... [24] link 'Endurax Extra Large Camera Backpack ...' text '$119.99' ...
```

## 2. 五个维度：每维只问自己一句话

| 维度 | 问自己 | 4 分的样子 | 1 分的样子 |
|---|---|---|---|
| `backtrack_and_explore` | 走错路时，它**知道退回去换条路**吗？ | 发现不对 → 明确回退 → 换策略且有效 | 从不回头，一条道走到黑 |
| `task_decomposition` | 它**把任务拆成步骤**了吗？ | 计划清楚、按子目标推进、覆盖全部要求 | 无计划，乱点 |
| `observation_reading` | 它**真的在读页面**吗？ | 准确引用页面上的名称/价格/按钮/提示 | 基本不读，凭想象说"页面上应该有…" |
| `self_verification` | 它**核对结果**了吗？ | 用页面证据确认（看到 "Added"、核对价格、重读购物车） | 直接宣布成功，没有任何核对 |
| `objective_quality` | **只看目标这句话**：够具体吗？ | 有对象、有条件、有成功标准 | "买点有用的东西"这种 |

---

## 3. 评分锚点（购物场景）

### 3.1 backtrack_and_explore

| 分 | 标准 |
|---|---|
| 4 | 明确判断"这条路不对"，主动 `go_back` / 重新搜索 / 换商品，且新路径明显更优 |
| 3 | 会回退，但不够及时（试错多步才回头），或换的替代方案一般 |
| 2 | 意识到要走回头路，但动作做错了（点错、回错了页） |
| 1 | 一直重复无效动作，从不尝试别的路径 |
| **N/A** | 全程没走错路，任务本身就一次通过（例如只搜一次就答对） |

> N/A 不是"懒得评"，而是"这条轨迹没有回退的机会"。两个条件同时满足才填 N/A：
> ① 轨迹里没有出现错误分支；② 客观上也不需要（例如两步就完成）。

### 3.2 task_decomposition

| 分 | 标准 |
|---|---|
| 4 | 理由里能看出子目标（先搜索 → 再筛选 → 再核对 → 再答），且每一步服务于整体 |
| 3 | 有大致计划，但漏了子步骤（例如没核对"第一个"是不是首页第一条） |
| 2 | 边点边想，没有整体计划，但方向不算完全错 |
| 1 | 完全没拆解，动作和目标无关 |

### 3.3 observation_reading

| 分 | 标准 |
|---|---|
| 4 | 每步都准确说出页面上的具体信息（商品名、价格、按钮名、"no results" 提示） |
| 3 | 大体读对，但漏掉关键信息（例如没注意到有多页、没注意规格必选） |
| 2 | 只读到一部分，部分结论没有页面依据 |
| 1 | 基本不读，直接凭常识作答；或引用了页面上根本不存在的内容 |

### 3.4 self_verification

| 分 | 标准 |
|---|---|
| 4 | 用页面证据闭环确认（看到 "Added to your shopping cart"、重新打开购物车、核对价格与目标条件） |
| 3 | 有核对动作，但不完整（例如只看了按钮变化，没确认购物车） |
| 2 | 只在嘴上说"应该成功了"，没有任何核对动作 |
| 1 | 完全不检查，直接宣布完成 |

### 3.5 objective_quality（**只看目标文本**）

| 分 | 标准 | 例子 |
|---|---|---|
| 4 | 对象、条件、成功标准都明确 | "Search for 'backpack' and report the price of the first product in the results." |
| 3 | 大体明确，但少一个要素 | "Add a product under $20 to your cart."（没说搜什么） |
| 2 | 有可执行成分也有模糊成分 | "Find a cheap backpack and add it to the cart."（"cheap" 没标准） |
| 1 | 纯探索，没有具体目标 | "Get something useful for the kitchen." / "Buy a nice gift for a friend." |

## 4. 两条完整示例

### 示例 A：t01（2 步：搜索 → 报价格）

```
1. submit(8,"backpack")        理由：需要搜索 backpack
2. send_msg_to_user("... Endurax ... $119.99")   理由：结果第一条是 Endurax，价格 119.99
```

| 维度 | 打分 | 理由 |
|---|---|---|
| backtrack | **N/A** | 两步完成，没有走错 |
| task_decomposition | **3** | 有"先搜再读"的顺序，但没说明如何确认"第一条" |
| observation_reading | **4** | 准确引用了商品名与价格，且与页面一致 |
| self_verification | **2** | 直接宣布答案，没有核对"第一条"确实是结果页第一条 |
| objective_quality | **4** | 明确：搜索词 + 要报告什么 |

### 示例 B：多步加购（搜索 → 点商品 → 选规格 → 加购失败 → 重选 → 成功）

```
1. submit(8,"coffee maker")
2. click(65)   → 打开 $11.31 的商品页
3. click(25)   → 选口味
4. click(35)   → 选规格
5. click(38)   → 加购，页面显示 "Added"
6. send_msg_to_user("已加入购物车：Caramel Swirl $11.31")
```

| 维度 | 打分 | 理由 |
|---|---|---|
| backtrack | **3** | 第 3 步加购失败后回退去补选项，处理正确但试错了一轮 |
| task_decomposition | **4** | 明确按"搜索→选品→补必选项→加购→核对"推进 |
| observation_reading | **4** | 注意到"缺必选规格"的报错，并据此行动 |
| self_verification | **4** | 用页面上的 "Added" 作为证据，不是空口宣称 |
| objective_quality | **3** | 有价格约束，但没说是哪类商品、也没说数量 |

> 注意：示例 B 的 agent 中途失败过一次，但因为**失败后处理得当**，backtrack 给 3 而不是 1。

## 5. 五个常见误判

| ❌ 错误 | ✅ 正确 |
|---|---|
| "任务这么简单，它做对了，给高分" | 简单任务看过程是否扎实；简单本身不是加分项 |
| "答对了 → self_verification 给 4" | 答对不等于核对过；要看他有没有检查动作 |
| "理由写得很长很漂亮 → observation 给 4" | 只认**页面里真实存在**的信息；编造的一律低分 |
| "含糊任务的 agent 表现不错 → objective_quality 给高" | 这一列只看目标文本，"给厨房买点东西"就是 1 分 |
| "拿不准就给 2.5" | 只填整数 1/2/3/4（backtrack 可填 N/A） |

## 6. 操作流程（建议两人独立标注）

```powershell
cd repro
# 1) 生成打分表（同时产出 CSV 和给人看的 Markdown）
.\.venv\Scripts\python.exe make_annotation_sheet.py

# 2) 每人复制一份，独立打分
copy annotations.csv annotations_a.csv
copy annotations.csv annotations_b.csv

# 3) 打开 annotations.md 逐条阅读，把分数填进各自的 CSV
#    不确定的记在备注里，不要互相商量

# 4) 两人都完成后，对比分歧，讨论后定一份 annotations_final.csv

# 5) 算与机器分数的相关性
.\.venv\Scripts\python.exe correlate.py --scores scores.json --annotations annotations_final.csv
```

**时间估计**：一条轨迹 2–4 分钟（10 条约半小时）。步数多的（8 步）会慢一些，建议先看 `n_steps` 再决定投入。

---

## 7. 两个提醒

1. **别把 `success` 当答案。** 它只说明"最终回答/购物车对不对"，与四个能力维度是两回事——我们正是要检验这两者的关系。
2. **同一批里保持尺度一致。** 如果第 3 条你给了 observation 3 分，第 8 条类似的表现也应该是 3 分；标注到一半如果发现尺度变了，回头统一一遍再交。
