## 为什么 B 批次不可用

B 的 10 条轨迹里有 **5 条被网络中断截断**（`meta.error` 含
`URLError: [SSL: UNEXPECTED_EOF_WHILE_READING]`），其中 3 条是 0 步的空轨迹：

```
t03_cheapest_backpack      0 步
t04_coffee_under_20        7 步后中断
t05_no_results             0 步
t09_vague_kitchen          1 步
t10_vague_gift             0 步
```

后果有两层：

1. **空轨迹的分数几乎必然一致**（人和 judge 都会给"什么都没做"低分），这类样本会**抬高**相关系数；
2. 剩下的 5 条里 `task_decomposition`、`objective_quality` 没有方差，`r` 直接算不出来。

所以 B 的 `r≈0.90` **不是"rubric 更准了"，是数据被网络打残了**。要用 B 作结论，必须重跑。

**已修的根因**：Dify Agent 应用只走流式，而 `dify_client` 的 `retries` 参数原先只作用于 blocking
分支——流式分支一次 TLS 抖动就抛，等于一条轨迹作废。现在流式路径也有指数退避重试（3 次），
实测把一条 0 步崩溃的任务救回成 2 步成功。

判分前先看一眼有没有失败的：

```powershell
Get-ChildItem output\runs\B2-refactor\trajectories\*.failed.json
.\.venv\Scripts\python.exe -c "import json,glob; [print(p.split(chr(92))[-1][:-5], json.load(open(p,encoding='utf-8'))['meta']['error']) for p in glob.glob('output/runs/B2-refactor/trajectories/*.json') if json.load(open(p,encoding='utf-8'))['meta'].get('error')]"
```

有 `error` 的轨迹，`correlate` 会提示条数；必要时加 `--exclude-errors` 单独看"只算正常结束的"版本。

## 要重标一批时怎么做

```powershell
# 1) 生成空白打分表（目标表已填时会被拒绝，这正是保护）
.\.venv\Scripts\python.exe code\make_annotation_sheet.py --input output\runs\<run>\trajectories

# 2) 复制两份，两位同学各自独立打分（不讨论），对照 annotations.md
# 3) 讨论分歧后合并，重算相关性
.\.venv\Scripts\python.exe code\correlate.py --scores output\runs\<run>\scores.json
```

只有"两人独立标注 + 算 Cohen's κ"才能把「单标注者」这个弱点降级；目前两批都是单人标注。

## 编码

用 Excel / WPS 打开 CSV 再保存，**默认会存成 GBK/ANSI**。

- `correlate.py` 会尝试 `utf-8-sig → gbk` 回退，能读，但会打一行提示；
- 想让文件本身干净，用：

```powershell
.\.venv\Scripts\python.exe code\normalize_annotations.py            # 处理 output/runs/*/annotations.csv
.\.venv\Scripts\python.exe code\normalize_annotations.py 路径        # 只处理一个文件
```

它会把原件备份成 `annotations.gbk.csv` 再转成 UTF-8（带 BOM），已经是 UTF-8 的文件会跳过。
**文件在 Excel 里打开时无法写入**，会提示"文件被占用"。
