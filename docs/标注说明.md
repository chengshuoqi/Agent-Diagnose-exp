## 二、必须知道的一件事：两批的标注尺度不同

这是本实验最容易读错的地方。同一个标注人、同一份打分指南，两批分数的分布却明显不一样：

| 维度 | A 的人工分 | A 均值 | B 的人工分 | B 均值 |
|---|---|---|---|---|
| task_decomposition | 4,4,1,3,1,2,4,4,4,3 | 3.00 | 4,4,4,2,4,4,4,4,4,3 | **3.70** |
| observation_reading | 4,4,1,2,1,2,4,3,4,3 | 2.80 | 4,4,3,2,4,4,4,3,4,3 | **3.50** |
| self_verification | 3,4,1,1,1,1,4,3,4,2 | 2.40 | 3,4,3,2,4,4,4,3,4,2 | **3.30** |

A 用了 1–4 全区间，B 向 4 聚集。而两批的**机器分分布相近**。结果就是 B 的人工列方差塌缩，
相关系数从 0.81 掉到 0.47——**agent 变好了（成功率 4/10 → 7/10），r 反而变低。**

原因很可能是「B 的 agent 明显更好，标注人把没出错整体读成 4 分」。但**单人标注无法区分
「尺度漂移」与「真实差异」**，这是本实验最大的方法学缺口。要修就得双人独立标注 + 算 Cohen's κ
（见 issue #10）。

## 三、重标一批的流程

```powershell
cd repro

# 1) 生成空白打分表（目标表已填时会被拒绝，这正是保护）
.\.venv\Scripts\python.exe code\make_annotation_sheet.py --input output\runs\<run>\trajectories

# 2) 对照 <run>\annotations.md 填五列
#    backtrack_and_explore 可填 N/A 或留空；其余填 1–4 整数

# 3) 算相关性（会先做 provenance 校验）
.\.venv\Scripts\python.exe code\correlate.py --scores output\runs\<run>\scores.json
```

标完先自检一次编码与填充量：

```powershell
.\.venv\Scripts\python.exe -c "import csv; r=list(csv.DictReader(open(r'output\runs\<run>\annotations.csv',encoding='utf-8-sig'))); print('rows', len(r)); print('filled', sum(1 for x in r for k in list(x)[6:] if (x[k] or '').strip()))"
```

期望 `filled` 在 40–50 之间（`backtrack` 的 N/A 不计）。

## 四、编码

用 Excel / WPS 打开 CSV 再保存，**默认会存成 GBK/ANSI**。

- `correlate.py` 会按 `utf-8-sig → gbk` 回退读取，能读，但会打一行提示；
- 想让文件本身干净：

```powershell
.\.venv\Scripts\python.exe code\normalize_annotations.py                    # 处理 output/runs/*/annotations.csv
.\.venv\Scripts\python.exe code\normalize_annotations.py <路径>              # 只处理一个文件
```

它会把原件备份成 `annotations.gbk.csv` 再转成 UTF-8（带 BOM）；已是 UTF-8 的会跳过。
**文件在 Excel 里打开时无法写入**，会提示「文件被占用」。
